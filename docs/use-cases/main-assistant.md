# 几个助手做事，Muse 给你一份完整的报告

Instinct 订餐厅，Grok Bot 查机票，Today 整理行程笔记。你希望一位主助手掌握这些结果，再告诉你整体进展。

## 让结果经过同一个信箱

```text
Today / Instinct / Grok Bot → Waypost → Muse → 你
```

其他助手分别拥有连接身份，按授权向 Muse 投递。Waypost 保存交接内容，Muse 从自己的信箱收取，再继续处理。

## 汇总里有什么

Muse 可以给你这样一份报告：

> 餐厅已确认周五 19:00 的两人位。机票有一个预算内候选，还没有购票。行程笔记已补全，请先决定出发日期和航班。

这是一种配置示例。助手名称和任务用于解释流程；实际接入需要对应运行环境支持 HTTP MCP 或 HTTP API。

## 先接入，再明确授权

1. 接入 Muse，为它开启收信、回执和发信能力。
2. 接入其他助手，签发允许向 Muse 发信的连接。发信时明确指定 Muse 为收件人。
3. 在各自的运行环境中配置连接，并请 Muse 收取、汇总和向你汇报。

新连接默认只向你发信。增加向 Muse 发信的权限，不会自动改变默认收件人；新连接也不会撤销旧连接。

## 结果由你掌握

Muse 发给你的报告出现在个人信箱中，其他助手之间的交接可以在“管理 → 全部消息”核对。你可以撤销连接，停止后续访问与发布。

Muse 的执行和定时收信由它的运行环境安排。Waypost 的处理回执是客户端报告的阶段，不代表外部预约、购买或任务已经成功。
