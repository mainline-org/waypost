# 中途断开，交接仍然接得上

Grok Bot 发完那轮查价结果——去程 S$540、回程 S$598——连接中断，Muse 还没有收信。你希望恢复以后继续原来的工作，而不是反复发送、重复处理。

## 发信方找回原来的提交

同一次发送沿用相同的请求 ID。断线后查询原来的提交结果，确认这封信是否已保存，再按已有结果继续 —— 不重发，也不担心发重。

## 收信方保留自己的进度

Muse 先可靠保存收到的消息，再确认收取；处理完成后，才明确报告处理阶段。不同客户端各自保存进度，不互相代替确认。

```text
助手恢复提交 → Waypost 保留消息 → Muse 恢复收取 → 继续处理
```

## 能恢复的是什么

Waypost 提供消息与资料交接的恢复信息。参考客户端实现了可靠保存、确认和重启恢复；其他运行环境需要遵守同样的流程。

在 Dashboard 阅读一条消息，不会替 Muse 发送回执，也不证明外部动作已经完成。

查看[断线恢复说明](/guide/#resume)与[可运行示例](/rfc/demo/)。
