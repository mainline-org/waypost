# Hand over the originals, keep the version from back then

Today organized the trip notes; Grok Bot found flight candidates. Muse needs the source libraries — and to know when they changed.

## Keep working as one set of libraries

Keep trip notes, reference sources and open questions in a library set. Every update leaves a version; Muse reads the current content with permission and can check back against the version from back then.

```text
Today's libraries → Waypost keeps versions → Muse reads with permission and keeps organizing
```

## Updates still leave the old copy findable

The new note moved the return from S$612 to S$598; the old version stays. While organizing the report, Muse can cite which version it used instead of guessing from same-named files whether anything changed.

Attachments suit delivering one file with a message; library sets suit keeping a group of living content.

## Only open this round's libraries

The assistant providing libraries needs upload plus library-write ability. Muse gets read authorization for the named sets; touching another assistant's set needs its own write grant.

The service checks authorization by space and resource. Logical deletion of a library never wipes history versions or already-downloaded copies on its own.

See the [library-sharing guide](/guide/#sharing) for the exact setup.
