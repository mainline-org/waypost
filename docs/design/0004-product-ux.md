# Dashboard 与主页的产品路径复核

用户需求：几个助手各自工作，希望一次看清结果，必要时查看来源资料，而不是逐个追问和复制内容。

本轮基于 `ca45211`，保留既有授权、邀请、回执和资料版本功能，在独立 worktree 避开未提交的 i18n。

| 问题 | 用户受到的影响 | 本轮改进 |
|---|---|---|
| 侧边栏无独立滚动 | 640px 高度展开菜单后达 1014px，退出按钮在视口外 | 桌面导航独立滚动，退出区域保留；手机保留页面滚动 |
| 邀请、新建空间、登录重置与个人信箱混排 | 不知道邀请谁、是否共享当前数据、凭据给谁用 | 放入默认折叠的「服务管理」，明确新用户与当前空间所有者 |
| 点击登录凭据入口即签发或重置 | 还未理解作用便可能使旧登录失效 | 先显示目标与影响，再明确生成、重置或重新启用 |
| 已选主助手时，空信箱仍要求接入发第一封信 | 结果已经交给主助手，用户误以为投递失败 | 等待汇总的说明，连接配置与全空间交接查询入口 |
| 助手页缺少角色解释 | 将主助手理解为固定产品或默认获得权限 | 主助手是用户主要对话的助手；选择角色不授予收信或资料权限 |
| 助手「最近来信」只看用户入口 | 看不到发往主助手的结果 | 展示该助手在当前空间的最近交付 |
| 主页「助手」「资料」只是装饰 | 很难理解角色、资料来源与版本的实际用途 | 三个可操作面板，助手详情、主助手示例选择、文件与历史版本 |

主页先给出「几个助手，一份完整结果」的用户结果，再用预约、查价和行程资料展示如何交接。示例在浏览器内运行，不连接真实账户、不执行真实订单、不修改权限。资料来源与允许读取的范围分别解释。

验证覆盖隔离 Chrome 的 1280×640、1024×480、390×844、320×568 Dashboard，以及 1280、390、320px 主页交互。包括菜单展开、底部退出、无横向溢出、角色说明、登录重置确认、键盘切换、附件到资料与历史版本。
