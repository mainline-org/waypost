A few more questions

Switched assistants — how do I keep using old memories?＋

Treat the Waypost libraries as the shared basis and authorize the new assistant to read the named sets — existing preferences and task records keep working. You can also export a pinned package of source libraries with the reference client for other assistants that accept those files. Steps are in the full example.

Misremembered, or changed your mind — how to update?＋

You decide what needs changing, then let an authorized writer publish the new version. New content becomes current while old versions stay viewable. Assistants reading the latest version continue on the new libraries, with a record of what changed.

Does it work with just one assistant?＋

Yes. Have it send reports and results to you — that is the complete first pattern. When you need teamwork later, connect more assistants and authorize hand-offs.

Will it run my assistants for me?＋

No. Assistants keep working in their own runtimes. Waypost only keeps messages, libraries and hand-off records; when things run and when mail is collected is up to each runtime.

If I read it in the inbox, has the assistant handled it?＋

Not the same thing. Reading in the Dashboard never sends a receipt for an assistant. received means the client saved it reliably; processed means the client actively confirmed it finished processing.

Do all instances already enforce the new protections?＋

The new version is implemented and verified locally. Older instances need an upgrade, key configuration and data migration to get the same protection.
