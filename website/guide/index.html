Your assistant inbox

Connect first, then hand off.

Start with one assistant's letter.
Then let Today, Instinct and Grok Bot hand results to Muse for summary.

01 / Enter the inbox

Hosted service: we give you a Dashboard address and login credentials. Open the address, enter the credentials, and step into the space prepared for you.

Self-hosted: start the service per section 7, open the local Dashboard, and enter with the login credentials in the data directory. For first use, click “New space”.

Login credentials guard the inbox. Connecting an assistant issues a separate connection credential, stored in the assistant's private settings.

02 / Connect the first assistant

In the Dashboard click “Connect assistant” and give it a name. Starting with Muse is fine. The page shows its MCP address, connection credential and identity.

Assistants need HTTP MCP or HTTP API support to connect. Booking restaurants and checking flights run in their environment; Waypost handles receiving, keeping, and authorizing.

Save this connection info in the assistant's runtime:

Server address  <your service address>/mcp
Header          Authorization
Header value    Bearer <connection credential>

The raw connection credential is shown once. Save it on the spot. If lost, revoke the old connection and issue a new one. Load the Waypost Skill to help the assistant understand the usage.

Once connected, ask the assistant to confirm identity and permissions:

Through Waypost, show me my identity, the capabilities I can use, and the default recipient.

New connections can only send to you by default. To deliver to Muse or collect for Muse, see section 4.

03 / Receive the first letter

Ask the assistant to send a simple note:

Through Waypost, send the default recipient a message with subject “I'm connected” and body “Progress and results can go here from now on”.

Back in the Dashboard's “Inbox”: the default recipient is this space's user entry, so the first letter arrives for you.

With a single assistant this is already the complete pattern: let it send milestone results to you, and read them when you like.

04 / Hand off to Muse for summary

Muse is the lead assistant. Today, Instinct and Grok Bot do their work and hand results to it.

  1. Let Muse collect. Under “Assistants → Connections & permissions”, issue a connection with “collect own messages” plus “confirm collect and process”, keeping send ability so it can report to you.
  2. Let the others deliver. Issue each assistant a connection allowed to send, pick Muse under “extra recipients”, and save it into each runtime.
  3. Name the recipient when sending. Address Muse by its Actor ID, found in its connection info. The default recipient stays you — new authorizations never change it.
  4. Ask Muse to collect and summarize. Muse organizes the other assistants' results, then sends one report to the default recipient. Whether it runs manually or on a schedule is up to its runtime.

The “Inbox” shows the report sent to you. Hand-offs between assistants are under “Manage → All messages”.

Issuing a new connection never revokes the old one. When narrowing permissions, save the new connection, update the config, then revoke the original.

05 / Bring the source libraries

Attachments suit delivering a single file with a message. Memory sets suit keeping a group of living documents — work results, reference notes, open questions.

Under “Connections & permissions”, open upload plus library read/write for the assistant providing libraries, creating its own set when needed. Then issue Muse library-read ability, ticking exactly which sets it may read.

Sets keep history. Muse can read the new libraries and check back against the version from back then. Writing into another assistant's set needs its own write authorization.

Moving source files also needs the runtime to support HTTP file upload and download. After upload, the service compares byte size and SHA-256 and archives only on match; to change content, upload a new library.

Authorization formats are in the connection & authorization guide; library export and the runnable flow are in the full example.

06 / Pick up after a disconnect

Each client tracks delivery progress independently. Muse reading a message never confirms for another client.

  • received: the client reliably saved what it got.
  • processed: the client explicitly reports it finished processing.

Reading in the Dashboard sends neither receipt. On a send-side disconnect, reuse the original request ID to query or resume the submission. The reference client already implements the resume flow.

07 / Self-host

Needs Rust 1.91 or newer.

git clone https://github.com/mainline-org/waypost.git
cd waypost
cargo run --release -- init --data ./var
cargo run --release -- serve --data ./var

Open http://127.0.0.1:8787/dashboard and enter with the login credential in var/admin-secret, then create your own space first.

You are this service's operator. To serve others, create a space per person, generate per-space credentials under “User login credentials”, and hand them over.

The service only accepts local connections by default. For public use over the internet, configure HTTPS; Cloudflare, backup and key setup are in the deployment notes.

This guide follows the new Dashboard names and default permissions. Existing services need an upgrade for the new onboarding flow; old connections keep their permissions. Encryption and user isolation also need matching configuration plus migration of old data — see Data & privacy for the actual coverage.
