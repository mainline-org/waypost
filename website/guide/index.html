你的助手信箱

先接入，再交接。

先收到一个助手的来信。
再把接入助手的结果交给主助手汇总。

01 / 进入信箱

托管服务：先申请邀请。收到私密链接后，打开它，保存个人登录凭据。下次用凭据进入自己的空间。

自己运行：按第 7 节启动服务，打开本机 Dashboard，用数据目录里的服务管理密钥进入。在「服务管理 → 创建用户空间」准备自己的空间。

个人登录凭据只管理你的信箱。接入助手时会另外签发一份连接凭据，存进助手的私密设置；服务管理密钥只供运行者维护服务。

02 / 接入第一个助手

在 Dashboard 点「接入助手」，给它取个名字。现在正在对话的助手也可以接入。页面会展示它的 MCP 地址、连接凭据和身份。

助手需要支持 HTTP MCP 或 HTTP API 才能接入。订餐厅、查机票这类工作由运行环境完成；Waypost 负责收信、留存和授权。

在助手的运行环境里保存这些连接信息：

服务地址  <你的服务地址>/mcp
请求头    Authorization
请求头值  Bearer <连接凭据>

原始连接凭据只展示一次。当场存好。遗失后撤销旧连接，重新签发。可以加载 Waypost Skill，帮助助手理解用法。

接好后，请助手确认身份和权限：

通过 Waypost 查看我的身份、可以使用的能力和默认收件人。

首次接入只有发信能力。未选择主助手时，默认向你发信；向主助手交付结果，见第 4 节。

03 / 收到第一封信

请助手发一条简单的通知：

通过 Waypost 给默认收件人发一条消息，主题是「我已接入」，正文是「以后可以把进展和结果发到这里」。

回到 Dashboard 的「信箱」。消息送往这份连接的默认收件人。发给你的，在「信箱」确认；发给主助手的，由它收取，也可在「记录与隐私 → 全部消息」核对。

只用一个助手时，这就是完整的用法：让它把阶段结果发给你，你有空时再看。

04 / 让主助手汇总

主助手是你主要对话的助手，接入助手把各自的结果交给它。你现在使用的助手也可以担任主助手；选择哪个产品，由你决定。

  1. 选定主助手。接入后，在「助手」页选择「选为主助手」，按提示签发收信、回执和发信权限。
  2. 接入其他助手。默认收件人选择主助手，保存各自的连接信息。它们仍只有发信能力，不必在每封信中手填收件人 ID。
  3. 请主助手汇报。让它收取结果、整理需要你决定的事，再给你发一封报告。何时执行与收信，由它的运行环境安排。

选定角色不自动扩大权限。更换主助手不会改写旧连接；需要新的投递目标时，签发新连接，并明确撤销旧连接。

「信箱」显示发给你的报告。助手之间的交接，在「记录与隐私 → 全部消息」查看。

05 / 带上原始资料

附件适合随消息交付单个文件。记忆集合适合保存一组会持续更新的资料，例如工作结果、参考笔记和待确认的问题。

在「连接与权限」中，为提供资料的助手开放上传与资料读写，需要时创建它自己的集合。再为主助手签发资料读取能力，明确勾选允许读取的集合。写入其他助手的集合，需要单独的写入授权。

查看和修改：在「资料」打开集合的「详情」，通过「查看版本」选择当前或历史版本。点击当前版本里的文本文件，修改内容，再点「保存为新版本」。历史版本只读，旧内容保留。若其他助手先更新了同一集合，保存会提示版本冲突，草稿仍留在编辑框；先复制保管草稿，再重新打开当前版本比较后保存，避免覆盖他人的更新。

带走资料：选好版本后，点「导出这个版本」。浏览器下载 ZIP，里面有 manifest.json、该版本仍有效文件的原始字节和删除标记；文件的原始路径与来源记录在清单中。已删除条目的旧正文不在当前包内，需要时选择删除前的历史版本另行导出。

网页导出最多 32 MiB、10,000 条资料，适合单个集合的选定版本。更大的集合可使用参考客户端。这份 ZIP 不包含完整消息、账号权限和全部历史，不能代替整个服务的备份；自行运行时请按部署说明备份数据库、完整对象目录和独立密钥。

交换原始文件还要求运行环境支持 HTTP 文件上传与下载。上传后，服务比对字节大小和 SHA-256，一致才接受封存；修改内容会保存为新资料版本。授权格式见接入与授权指南。

06 / 断开以后接着用

每个客户端独立记录收取进度。主助手读过一条消息，不会替其他客户端完成确认。

  • received：客户端已可靠保存收到的内容。
  • processed：客户端明确报告已完成处理。

Dashboard 查看不发送这些回执。发信时遇到断线，沿用原来的请求 ID 查询或恢复提交。参考客户端已实现恢复流程。

07 / 自己运行

需要 Rust 1.91 或更新版本。

git clone https://github.com/mainline-org/waypost.git
cd waypost
cargo run --release -- init --data ./var
cargo run --release -- serve --data ./var

打开 http://127.0.0.1:8787/dashboard，用 var/admin-secret 里的服务管理密钥进入，在「服务管理 → 创建用户空间」准备自己的空间。

你就是这套服务的运行者。让别人使用时，在「服务管理」点「邀请新用户」，为每人创建独立空间，将一次性链接通过私密渠道交给对方。

服务默认只接受本机连接。通过公网使用时需要配置 HTTPS；Cloudflare、备份和密钥配置见部署说明。

本指南按新版 Dashboard 的名称与默认权限说明。既有服务需要升级后才能使用新接入流程，旧连接保留原权限。加密与用户隔离还需相应配置和旧数据迁移，实际保护范围见数据与隐私。

08 / 试用范围与求助

我们在 Cloudflare 提供的托管服务目前按邀请试用，尚未开放付费订阅，收费和正式服务方案待定。来信是计划接入的独立产品，当前没有完成集成。

  • 单个文件最多 256 KiB，一封消息最多 4 个附件。
  • 一个资料集合的当前有效条目和删除标记合计最多 32 条。
  • 其他容量与连接权限，以助手调用 waypost_describe 返回的实际值为准。超过上限会被拒绝，账户级资源用量也可能影响服务。

请保留重要资料的本地副本并定期导出。试用暂不承诺 SLA 或响应时限，完整生产恢复演练尚未完成。

反馈故障：在 GitHub 提交问题，说明操作步骤、浏览器或助手运行环境版本、发生时间和错误代码。公开内容不要包含登录凭据、助手连接配置、完整邀请链接、私人消息、资料或未脱敏日志。

丢失凭据或需要重发邀请：沿最初收到邀请的私密渠道联系运行者。公开问题区不能用于重置身份；涉及私人内容的问题也请走这条私密渠道。
