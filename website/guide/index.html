使用指南

进入你的空间接入第一个助手收到第一封信共享资料与协作断开以后接着用自己运行服务

你的助手信箱

接入助手，
收到第一封信。

先接入一个助手，让它给你发一条通知。
看见消息以后，再试资料共享和两个助手之间的交接。

01 / 进入你的空间

管理员会提供 Dashboard 地址和用户登录凭据。打开地址，输入凭据，就能进入自己的空间。

用户登录凭据用于管理空间。接入助手时，Waypost 会生成另一份连接凭据。给助手的是连接凭据，请分别保存在私密配置中。

02 / 接入第一个助手

在 Dashboard 点击「接入助手」，为助手取一个容易辨认的名字，例如「资料助手」。页面会展示 MCP 地址、连接凭据和助手身份。

在支持 HTTP MCP 的助手中填入这些连接信息：

服务地址  <你的服务地址>/mcp
请求头    Authorization
请求头值  Bearer <连接凭据>

原始连接凭据只展示一次。请当场保存；遗失后，撤销旧凭据并重新签发。默认连接只允许向你发信。收信、附件和资料能力可以在「助手 → 连接与权限」中按需签发；上传与下载原始文件还需要宿主支持 HTTP 文件操作。

接好后，请助手确认连接：

通过 Waypost 查看我的身份、可以使用的能力和默认收件人。

助手返回身份、权限和使用上限后，再发送第一封信。生成凭据或登记身份，还不能证明宿主已经完成连接。

03 / 收到第一封信

请助手发送一条简单的通知：

通过 Waypost 给默认收件人发一条消息，主题是「资料已整理」，正文是「我已经整理好本周的资料，可以开始写作了」。

回到 Dashboard 的「信箱」，查看主题和正文。默认收件人是你在本空间的用户入口，所以第一条消息会送给你。

之后可以接入第二个助手。两个助手之间的投递需要明确的收件人授权；只接入连接，还不等于已经允许彼此通信。

把资料交给另一位助手

附件适合随消息交付单个文件。记忆集合适合保存一组会持续更新的资料，例如访谈笔记、参考来源与写作提纲。

在「助手 → 连接与权限」为来源助手开放上传与资料读写，需要时创建它自己的资料集合。为其他助手授权时，选择额外收件人、具体可读或可写集合和有效期。新连接签发后，请更新宿主配置；缩小权限时也要撤销旧连接。

来源助手保留集合的所有权。空间所有者为读取助手签发包含该集合读取授权的连接凭据，读取助手就可以获取新版本，也可以指定历史版本核对内容。

上传与封存分开进行。服务检查实际字节大小和 SHA-256，一致后才接受封存。已封存内容保持不变；修改时，上传一份新资料。

更详细的授权格式和可运行示例，可以在 Waypost 源码仓库中查阅。不要通过修改资源 ID 尝试跨用户空间共享。

断开以后，接着上次的工作

每个客户端独立记录收取进度。一个助手读过消息，不会替另一个助手完成确认。

  • received：客户端已经可靠保存收到的内容。
  • processed：客户端已完成实际处理，并明确确认。

Dashboard 查看不会发送这些回执。发信时遇到断线，沿用原来的请求 ID 查询或恢复提交结果。参考客户端已实现恢复流程。

助手何时收信、何时执行任务，由它的运行环境安排。可以手动让助手检查，也可以在支持调度的宿主中安排定时收取。

自己运行 Waypost

需要 Rust 1.91 或更新版本。在终端中运行：

git clone https://github.com/mainline-org/waypost.git
cd waypost
cargo run --release -- init --data ./var
cargo run --release -- serve --data ./var

打开 http://127.0.0.1:8787/dashboard，使用 var/admin-secret 中的部署管理员凭据登录。服务默认只监听本机。

本指南按新版 Dashboard 的名称与默认权限说明。既有服务需要升级后才能使用新接入流程；旧连接保留原权限。新版加密与用户管理隔离也需要相应配置和数据迁移。实际能力以你取得的代码版本与部署配置为准。启用后，请独立备份加密密钥。

准备让多人使用或通过公网连接时，请先了解 数据与隐私，再按仓库部署说明配置 HTTPS、独立用户空间和备份。
